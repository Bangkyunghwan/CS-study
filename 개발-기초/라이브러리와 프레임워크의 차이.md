### 라이브러리와 프레임워크의 차이

#### 라이브러리

라이브러리는 특정 기능을 나중에 가져다 쓸 수 있도록 미리 작성해 둔 함수나 클래스 등의 코드 집합이다.

예를 들어 문자열이 비어 있는지 확인하고 싶으면, 그 기능을 매번 직접 구현할 필요 없이 이미 만들어진 메서드를 내가 필요한 시점에 호출하면 된다.

문자열 변수가 비어 있는지 확인하고 싶음 → 직접 그 기능 개발 X → 빈 문자열 확인하는 라이브러리 메서드 가져다가 사용

#### 프레임워크

프레임워크는 특정 목적의 애플리케이션을 만들 때 반복해서 필요한 구조와 실행 흐름을 미리 구현해 둔 틀이다.

예를 들어 웹 애플리케이션에서는 HTTP 요청이 들어오면 어느 메서드를 실행할지 찾고, 요청에서 필요한 값을 꺼내 그 메서드에 전달해야 한다. Spring에는 이런 공통 흐름이 이미 구현돼 있다. 나는 그 틀에 맞춰 어떤 요청을 처리할지, 그 요청이 왔을 때 무슨 일을 할지 작성하면 된다.

웹 애플리케이션 만들고 싶음 → HTTP 요청을 받고 처리하고 응답하는 모든 과정 개발 X → 웹 개발 프레임워크 사용 + 요청에 따른 내가 원하는 동작 개발

#### 차이점

**라이브러리**는 내 코드에서 필요한 시점에 호출해서 사용한다. 예를 들어 특정 지점에서 문자열 변수가 비어 있는지 확인하고 싶으면, 그 지점에서 라이브러리 메서드를 호출하면 된다.

**프레임워크**는 자신이 맡은 실행 흐름에서 내 코드가 언제 실행될지 결정한다. 그래서 프레임워크의 규칙에 맞춰 내 코드를 연결해야 한다. 예를 들어 Spring에서 특정 HTTP 요청이 왔을 때 실행할 코드를 컨트롤러에 작성해 두면, 나중에 해당 요청이 들어왔을 때 Spring이 그 코드를 호출한다. 이런 방식을 제어의 역전(IoC)이라고 한다.

#### 스프링 코드에서 둘 다 찾아보기

```java
import org.apache.commons.lang3.StringUtils;

@RestController
class GreetingController {

    @GetMapping("/hello")
    public String hello(@RequestParam(name = "name", required = false) String name) {
        if (StringUtils.isBlank(name)) {
            return "안녕하세요!";
        }
        return name + "님, 안녕하세요!";
    }
}
```

여기서 사용한 라이브러리는 Apache Commons Lang이고, `StringUtils.isBlank(name)`은 그 라이브러리의 메서드를 호출하는 코드다. 이 메서드는 `name`이 `null`이거나, 빈 문자열이거나, 공백만 있는지 확인해 준다. `hello()` 안에서 이 검사를 언제 할지, 검사 결과에 따라 어떤 인사말을 반환할지는 내가 작성한 코드에서 정한다.

프레임워크는 여기서 웹 요청을 처리하는 Spring이다. 나는 아래 어노테이션들(규칙)로 내가 작성한 코드를 Spring의 요청 처리 흐름에 연결한다.

- `@RestController`는 이 클래스가 컨트롤러이고 메서드의 반환값을 HTTP 응답 본문으로 보낸다는 표시다.
- `@GetMapping("/hello")`는 `GET /hello` 요청을 이 메서드에 연결한다는 표시다.
- `@RequestParam(name = "name", required = false)`는 요청에 `name`이라는 파라미터가 있으면 그 값을 메서드 인자로 넘기고, 생략하면 `null`을 넘긴다는 뜻이다.

실제로 `GET /hello?name=민수`가 들어오면 Spring MVC가 `hello("민수")`를 호출한다. 그리고 `hello()` 안에서는 내가 작성한 코드가 `StringUtils.isBlank(name)`을 호출한다.

`GET /hello`처럼 `name`을 생략하면 Spring MVC가 `hello(null)`을 호출한다. 이때 `StringUtils.isBlank(name)`이 `true`를 반환하므로 기본 인사말인 `"안녕하세요!"`가 응답으로 나간다.

#### 내가 이해한 차이

가장 큰 차이는 실행 흐름을 누가 제어하느냐라고 생각한다. 라이브러리는 내가 필요한 시점에 호출해서 쓰고, 프레임워크는 자신이 맡은 흐름에서 정해진 조건이 되면 내 코드를 호출한다. 프레임워크의 규칙을 따른다는 건, 프레임워크가 내 코드를 찾아서 적절한 시점에 실행할 수 있도록 정해진 방식으로 연결해 준다는 뜻으로 이해했다.
